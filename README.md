# Прогноз голов и угловых в футбольном матче

До начала каждого матча модель оценивает четыре математических ожидания за 90 минут с добавленным временем: голы и угловые хозяев и гостей. Овертайм и пенальти не учитываются. Решение использует четыре модели CatBoost с пуассоновской функцией потерь и признаки только из доступной истории матчей.

В репозитории находятся итоговый прогнозный код, ноутбук, зависимости, тесты и [краткий отчёт](REPORT_RU.md). Исходные данные задания не распространяются. Для проверки запуска без них есть искусственный пример.

## Установка

Проверенное окружение — **Python 3.12**, macOS на Apple Silicon, CPU. GPU не нужен. Команды выполняются из корня проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --sys-prefix --name football-forecasting --display-name "Football forecasting (Python 3.12)"
```

## Данные

Для оценки на данных задания расположите файлы так:

```text
data/
  core_matches.parquet
  open_matches.parquet
  spring/
    core_matches.parquet
    open_matches.parquet
```

Первые две таблицы содержат историю до 01.03.2026 UTC. В `spring/` помещаются предоставленные проверяющей командой матчи за март–май 2026 в том же формате. Идентификатор `match_id` общий для таблиц. Предматчевое расписание берётся из весеннего `core_matches`; доступные результаты уже прошедших матчей — из `open_matches`.

Входные цели: `home_goals_90`, `away_goals_90`, `home_corners_90`, `away_corners_90`. Отсутствующие результаты остаются неизвестными. Ленты `feed*_events` для итоговой модели не требуются. Внешние данные и коэффициенты букмекеров не используются; отдельного загрузчика внешних данных нет.

Если данных задания нет, вместо этого создайте искусственный пример:

```bash
python make_demo_data.py
```

Генератор работает только при отсутствии каталога `data`, чтобы не перезаписать ваши файлы. Пример содержит 300 исторических и 6 будущих матчей. Он проверяет работоспособность, а не воспроизводит качество из отчёта.

## Запуск

После подготовки данных выполните ноутбук целиком:

```bash
jupyter execute solution.ipynb --kernel_name=football-forecasting --timeout=21600 --output=solution.executed.ipynb
```

Также можно открыть `solution.ipynb` в VS Code/Jupyter, выбрать созданное ядро Python 3.12 и выполнить все ячейки сверху вниз. Рабочим каталогом должен быть корень проекта с `src/` и `data/`.

**Последняя ячейка записывает `predictions_spring.parquet`** в корне проекта. Столбцы:

```text
match_id, home_goals, away_goals, home_corners, away_corners
```

По одной строке на каждый матч весеннего `core_matches`, в исходном порядке. Числа положительные и вещественные, без округления до целых. Дополнительно создаётся `run_audit.json` с параметрами обучения, проверкой заморозки и расходом ресурсов; терминальная команда сохраняет выполненный ноутбук в `solution.executed.ipynb`.

Модели обучаются один раз с границей 01.03.2026 UTC. Весной обновляется только история признаков. Из-за отсутствия времён публикации принято допущение: результат становится доступен через 24 часа после начала матча; равенство границе ещё не считается доступностью. Для обучения применяется та же задержка. Используется 6 потоков CPU.

## Проверки кода

Тесты используют искусственные данные и не требуют исходных таблиц задания:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Проверяются временные границы, независимость прогноза от текущего результата матча, обработка пропусков, неизменность моделей при прогнозировании и формат выходного файла. Подробности модели, экспериментов и ограничений приведены в [REPORT_RU.md](REPORT_RU.md).
